From LiDAR returns
to drivable ground.

We compress recent 3D returns into a layered height map, estimate a local ground surface, then require evidence of support and clearance before labeling a 10 cm cell free.

What is actually retained: experimental core 69d182ca…, including conservative boundary guards. It is not installed in Nav2. A newer signed-wall rule briefly improved coverage, but failed a stronger wall-edge test and was rolled back. This page explains both, without presenting the rejected rule as current behavior.

The experiments on this page

Use Isaac ground-truth poses to isolate terrain mapping from SLAM error. Simulator collision geometry supplies the evaluation reference only. The mapper receives points, time and sensor pose—not terrain labels.

The frame is re-anchored to the calibration platform; no cloud fitting or post-hoc pose correction is used to improve scores.

The live SLAM path is separate

GLIM’s global/submap optimization is disabled, but fixed-lag corrections still matter. Observation/revision interfaces and reconstruction checks exist; a live revision-aware terrain consumer and installation barrier remain unfinished.

Moving full ROS scans are still un-deskewed. SlamObservation contains GLIM-preprocessed evidence, not the raw native returns used here. The mapper does not itself repair pose-graph changes.

Latest shadow-evaluation checkpoint · moving GLIM tests still pending

Causal/revised pose association, native reconstruction and deterministic noise utilities now have regression tests. Export on the archived stationary GLIM recording passed for 496 revisions / 497 frames. These are foundations, not a completed noisy-SLAM experiment.

The input audit found that GLIM's untilted extrinsic does not match the 5° acquisition mount (5° / 1.19 cm discrepancy). An experiment-only corrected configuration is frozen; production is unchanged and live TF validation remains required. Current GLIM preprocessing also zeros per-point times via global_shutter_lidar=true, so rotating full-scan deskew is not established.

An isolated installed-Nav2 check confirms the soft inflation gradient but does not prove hard clearance: three of 1,932 tested poses pass center/perimeter cost checks despite padded-footprint intersections with the analytic wall, two also with the configured unpadded footprint. This is not a closed-loop collision result. It remains a failed diagnostic, not a reason to delay the broader moving-SLAM baseline. 02

The retained algorithm, in order

“Free” is the end of a chain of checks—not the absence of an occupied voxel. A late check may change an apparently supported cell back to unknown.

Validate observations

Audit native timestamps, poses, scan cadence and extrinsics. Keep finite returns within the sensor’s valid range. Transform points and the LiDAR origin consistently.

Accumulate layers

Bin by 10 cm XY cell. Match returns to up to three continuous-height layers within 2.5 cm of a layer mean. A fourth overflow layer is conservative evidence, never ground.

Fit local ground

Take lowest-layer means in a 9 × 9-cell neighborhood. Initialize from the low subset, robustly refit a plane, reject excessive slope or residual uncertainty.

Classify geometry

Compare layer heights to that plane. Check spatial support, surface normals and partial faces. Detect positive hazards; retain boundary uncertainty around discontinuities.

Check connection

Seed from nearby measured ground, then connect compatible ground patches with bounded links. Disconnected “floors” do not automatically become drivable.

Bound interpolation

Only fill eligible gaps with measured endpoints bracketing them in two nonparallel directions. Maximum span 30 cm; predicted heights must agree within 2 cm.

Certify whole cells

All four cell corners need surrounding, height-consistent ground witnesses with bounded span. A few good points near the center are insufficient.

Check clearance

Test sensor-to-ground paths against occupied columns. Restrict historical-view bypasses to actual retained observations. Unresolved occlusion returns to unknown.

What is retained per cell, and what is discarded?

The mapper does not retain a complete raw point-cloud map. Each layer has ≤1-second aggregation buckets with count, mean, covariance statistics, peak/trough positions, a small spatial-support certificate, two retained exact support positions, a 5 × 5 XY-presence mask and corner-sector evidence.

Bucket start times never refresh. At expiry, old buckets are removed and aggregates rebuilt. A shared bounded table keeps acquisition-time sensor origins for historical clearance checks. This is bounded recent evidence, not permanent reconstruction.

Spatial certificates can saturate after three distinct points separated by at least 3 mm. View evidence changes after 10 cm translation or 5° yaw. Repeated hits can improve statistics, but repetition alone does not supply missing XY geometry.

Ground and obstacle decisions in a little more detail
ground(x, y) = a·x + b·y + c
height residual = return.z − ground(return.x, return.y)
positive hazard evidence: peak residual + 2σ ≥ 0.08 m
plus spatial support or multiple-view evidence

The ground fit uses at least six samples, up to four refits, a 3 cm residual band, maximum slope magnitude 0.35 (rise/run), and maximum residual σ of 2 cm. σ has a 5 mm floor. Ground area support also checks XY covariance; a line of points is not a measured patch.

Sub-threshold side-face returns are not automatically traversable. Layer and joint-layer normal checks can keep them unknown. The retained wall guard conservatively withholds a one-cell neighborhood; its “negative edge” name does not guarantee that it represents a true downward discontinuity.

03

Ground support is not collision clearance

Why center points are not enough

Illustration, not a recorded map. A cell can contain genuine ground returns and still straddle a hole. The whole-cell support check is why some well-observed cells remain unknown.

The corner certificate

The fast path collects real ground support in all eight 45° sectors around a corner. The slower path examines retained points and bounded XY-presence regions, not invented region-center returns.

An angular fallback accepts sufficient actual bearings with every uncertainty-bounded circular gap strictly below 90°. Witness pairs must still fit within the existing 30 cm span. Neighboring planes must agree within 2 cm.

Important limit: this is a local-support assumption. Even four supported corners do not prove that an unsampled thin obstacle cannot cross a small portion of the cell interior. Boundary extent protection is still necessary.

What each output label means
CostMeaning in this experimental output
−1Unknown / not certified. Could be missing returns, a failed ground model, an edge, insufficient extent or occlusion. Not necessarily an obstacle.
0Measured traversable ground after all applicable checks.
20Traversable with extra cost: inferred ground or measured roughness. Read the reason code to distinguish them.

The six output channels are cost, reason, estimated ground height, uncertainty, obstacle height and evidence age. These are not yet a validated Nav2 footprint-aware costmap interface.

The failure that changed the conclusion

A candidate stopped treating an upward-facing wall as a dropoff. It passed the recorded courses and slightly improved coverage. But a rotated wall can cross a tiny cell-corner sliver between sampled returns. Removing the guard made that sliver free.

Failure A · Sign ≠ extent

The old guard keeps the sliver non-free. The candidate has surrounding floor support but no return from the wall inside that particular cell. Its cost becomes free even though the continuous face intersects it.

Next requirement: preserve a conservative bound on a face’s extent through neighboring cells. A correct up/down label alone cannot certify clearance.

Failure B · Lowest ≠ drivable ground

The local fit can follow the low hole wall: one fixture estimates about −4.5 cm where the driving surface is near +5 cm. Both retained and rejected cores exhibit this. Hole probes stay non-free, but the ground reference and edge reason can be wrong.

Next requirement: anchor the driving surface to supported, connected ground rather than trusting the lowest local samples.

What is still limited

  • Longer, stop-heavy routes and settled rotation have much worse coverage; motion pattern and evidence age matter.
  • Angular support and span dominate remaining extent failures. More hits at the same positions need not fix them.
  • The capacity stress profile nearly fills the 1 GiB budget. Replay timing is not live ROS timing.
  • Robot wheel support, body clearance and pose-revision installation need a shared, validated interface before navigation.

Guardrails worked: a better headline coverage number did not override the later wall false-free failure.

Ways to explore it yourself

The browser viewer above is the easiest visual demo. Nothing on this page moves the robot, starts Isaac, or loads a live navigation stack.

1 · Open this walkthrough — no dependencies

Open this HTML file directly, or run this from the repository root to serve it and its source links on localhost:

python3 -m http.server 8088 --bind 127.0.0.1

Then open http://127.0.0.1:8088/docs/implementation/terrain-algorithm-overview.html. If working over SSH, forward port 8088 to your computer. Embedded diagrams and the recorded figure work without the external drive. Stop the server with Ctrl+C when finished.

2 · Run the small C++/Python fixtures — no simulator

These commands use the already-prepared astrobot-repair-dev container and its /tmp/repair-* build. If that container/build no longer exists, rebuild the ROS overlay as described in AGENTS.md; do not assume the temporary paths are permanent.

docker exec -it astrobot-repair-dev bash
source /etc/ros_setup.sh
source /tmp/repair-install/setup.bash
cd /workspace/astrobot-lab

cmake --build /tmp/repair-build/slam_mapping \
  --target layered_terrain layered_terrain_diagnostics test_layered_terrain -j 2

TERRAIN_LIBRARY=/tmp/repair-build/slam_mapping/liblayered_terrain.so \
TERRAIN_DIAGNOSTIC_LIBRARY=/tmp/repair-build/slam_mapping/liblayered_terrain_diagnostics.so \
python3 -m pytest -p no:cacheprovider -v tools/test/test_terrain_diagnostics.py

ctest --test-dir /tmp/repair-build/slam_mapping --output-on-failure

Expected for this snapshot: 108 face-fixture cases pass (three surfaces × four offsets × three rotations × three slopes), plus seven mapper CTest programs. These are contracts, not an interactive GUI. Their wall/hole probes supply evaluation truth only. The complete sourced suite currently has 429 Python tests and 11 CTest programs.

3 · Replay an actual capture and plot its terrain map — external archive required

No GPU or running simulator is needed for replay. Use the archive-mounted dev container. Verify the external device is mounted and the simulator is stopped first. Runs are exclusive-create; a missing archive is a hard stop, never a reason to write the replay to the root disk.

# On the host; do not proceed if the mount is absent:
findmnt /media/jacoblambert/6c8aadd0-9332-4357-aea4-437b6aadef261
docker ps --format '{{.Names}} {{.Status}}'

docker exec -it --user 1000:1000 astrobot-revision-dev-v2 bash
source /etc/ros_setup.sh
source /tmp/repair-install/setup.bash
cd /workspace/astrobot-lab
df -h /archive

python3 tools/audit_native_terrain.py \
  /archive/revision-80479640be564a4d9ac489dfed0e86cb

python3 tools/replay_native_terrain.py \
  /archive/revision-80479640be564a4d9ac489dfed0e86cb \
  --reference-capture /archive/revision-8b1edba87feb4c60a637249a9b7852d7 \
  --library /archive/revision-bf1fde8ac66a45979c61a8404232e8f0/liblayered_terrain.so \
  --grid-phase .025

The replay prints a fresh Run: /archive/revision-…. Set that exact path below, then create its figure and coverage breakdown once:

terrain_score_run=/archive/revision-PASTE_THE_PRINTED_ID
python3 tools/plot_terrain_calibration.py \
  /archive/revision-80479640be564a4d9ac489dfed0e86cb "$terrain_score_run"

The native audit’s eligible_for_moving_replay: false does not unlock undeskewed ROS full scans. This separate native replayer enforces its own route, timing, pose and geometry gates. An audit printout alone is not terrain acceptance.

4 · Inspect why cells were rejected

In the same archive-mounted shell, run a fresh native replay with the diagnostic library and explicit flag:

python3 tools/replay_native_terrain.py \
  /archive/revision-80479640be564a4d9ac489dfed0e86cb \
  --reference-capture /archive/revision-8b1edba87feb4c60a637249a9b7852d7 \
  --library /archive/revision-8b46e0e7666040cd80f9f32b93013686/liblayered_terrain_diagnostics.so \
  --diagnostics --grid-phase .025

Run the coverage diagnostic command from demo 3 on its new output. It adds rejection_details: few directions, angular gap, span, missing anchor, plane disagreement, and boundary-source flags. Final cell/corner arrays are in diagnostics_*.npz; sequence counts are in terrain_diagnostics.json.

Diagnostic timings are excluded from acceptance. The instrumented target is not installed by the ordinary build. Diagnostics were checked for exact map equivalence at all four offsets.
