Launch ownership: terrain_shadow.launch.py → glim_live.launch.py → localization supervisor, which manages the GLIM process. The shadow launch starts synthetic RTK but no goal sender or Nav2.

Where do exploration, return-home and operator control fit?

The existing Phase 4 launch adds the exploration manager above navigation. It selects exploration/resource candidates, prechecks planner reachability, tracks goal progress and blacklists failures. Return-home can use recorded breadcrumbs and bounded waypoint goals. These mission policies depend on the older BEV path; they are not exercised by the current GT-controlled loop.

The command mux arbitrates namespaced cmd_vel_nav and cmd_vel_teleop into cmd_vel, honoring control/estop, control/mode, freshness and configured localization gating. In automatic arbitration, fresh teleop takes priority; explicit nav/teleop modes select their source. Hold/stale inputs produce zero commands.

In shadow acquisition, the independently guarded simulator driver owns the velocity topic instead. Never launch both owners. Breadcrumb return, recovery jitter and exploration policy cannot compensate for an invalid surface map or an unsafe collision checker; they remain downstream integration work.

04 / The foundation

Frames: never compare different physical centers

A pose is only meaningful with its parent frame, physical body and acquisition time. GLIM estimates the IMU body; GT reports base_link; terrain points originate at the LiDAR. The mount is off-center and rotated.

Exact transform contract

Let T_A_B transform coordinates from frame B into frame A. At measurement time t:

T_map_lidar(t) = T_map_imu(t) · T_imu_lidar
T_map_base(t)  = T_map_imu(t) · inverse(T_base_imu)
T_map_base_GT  = T_map_world · T_world_base_GT

point_map  = T_map_lidar(t) · point_lidar
origin_map = T_map_lidar(t) · [0, 0, 0, 1]

Interpolate the IMU pose (translation + quaternion SLERP), then apply the rigid extrinsic. Interpolating LiDAR positions directly across a turn would incorrectly smooth the rotating lever arm.

Physical mount / world origin

  • Fixed home in world: [-20, -20, 0]. Map position is world position minus home: world (20,18) becomes map (40,38).
  • LiDAR parent mount: base translation approximately [0.40, 0, 0.25] m. Current natural experiments use an opt-in +5° pitch.
  • IMU mount: approximately [0.264, 0.01728, 0.26247] m, near 180° yaw relative to base.
  • Use the recorded/audited imu_from_lidar and USD/TF checks as authority, not these rounded numbers.

Frame checks that must remain true

  1. Same body: simulator physics root and USD base_link agree. Wheel centers are symmetric about base XY (x ±0.256 m, y ±0.2854 m). Center of mass and instantaneous skid-steer turning center are not interchangeable with that body frame.
  2. Same acquisition: published GT and native sensor geometry match the same physics snapshot. The allowed 2 ns difference addresses round-versus-truncate representation only; it does not allow missing-tick interpolation or time fitting.
  3. Same mount: published TF matches the actual pitched LiDAR parent geometry. A frozen mount-corrected GLIM config is used; default config is not automatically equivalent.
  4. Same global origin: the evaluator uses the declared home transform. It does not optimize a best-fit SE(3) or shift timestamps to make GLIM look accurate.
  5. Single TF authority: capture uses OMNILRS_GT_TF_ENABLED=false. GT topics remain available. The legacy map→odom bridge must use same-time corrected pose and odometry; no competing GT broadcaster.

Audit sources: live GLIM accuracy, shadow input/mount audit, TF fixture audit, simulator GT probe, legacy TF bridge.

05 / Causality, not just coordinates

Native timing, first publication and pose revisions

What the scanner actually delivers

The mechanical scan is built over time. Native batches are rigid simulator acquisition chunks at about 30 Hz; the ROS full scan accumulates multiple chunks at nominal 10 Hz. Full scans are currently un-deskewed.

Terrain uses native chunks to avoid pretending a moving full scan has one valid pose. GLIM still consumes the full-scan stream. Slow motion reduces that error; it does not remove the timing distinction.

What GLIM currently optimizes

The frozen experiment uses CPU GICP, physics IMU and 1.62 m/s² lunar gravity, plus absolute aiding. Submap/global optimization is disabled in its config, even though the global-mapping module can be enabled.

Local fixed-lag ODOM revisions still occur. Disabling loop closure does not make all historical poses immutable.

The live contract

  • No extrapolation: require a measurement-time pose bracket with at most 200 ms gap, available by the 200 ms association deadline.
  • Conservative receipt: callbacks are logged in actual order, then assigned the next received clock as an availability bound. Wall receipt timestamps are also retained. Executor backlog means this is not exact sensor-to-wall latency.
  • Monotonic evidence: project at a 200 ms delayed, 100 ms-quantized acquisition watermark. This prevents map expiry/projection from moving past data that are still legitimately waiting for poses.
  • Bounded state: at most 128 queued chunks / 32 MiB; pose-history cap 2,048 frames. Capture UUID, contiguous sequence from zero, session, epoch and revision ancestry are checked.
  • First publication only: later local corrections are recorded but do not retroactively move already-integrated terrain. Final-revised trajectory accuracy is a separate retrospective diagnostic.
  • Fail closed: resets, unsupported non-ODOM revisions, missing/duplicate inputs, extrinsic changes, missed deadlines and stale clock/input invalidate the advisory map. Its wall heartbeat is independent of simulation time.
Pose-graph scaffolding ≠ correction-aware live terrain.SlamRevision carries ODOM=1, SUBMAP=2 and GLOBAL=3 updates, and retained-observation/snapshot foundations exist. This live first-publication mapper rejects non-ODOM updates rather than silently keeping old geometry. Before enabling graph optimization, implement and validate retained-evidence rebuild/reintegration. Evidence decay is not a pose-graph correction strategy.
Known shutdown gap, not hidden by “fail closed”.An earlier SIGINT interrupted a callback after integration but before projection, leaving completed:false alongside final valid:true. Diagnostics expose the unprojected tail and reject completion. Shutdown invalidation/flush handling still needs a fix before any downstream authority is granted.

Core implementation: ShadowCore, ReceiptScheduler, ROS wrapper; wire contracts: SlamRevision and SlamFramePose.

06 / The mapper itself

A supported surface, not “empty voxels = free”

The experimental core stores compact geometric evidence in XY cells and continuous-height layers. It asks whether a local ground surface exists, whether it has hazards, and whether the whole output cell is sufficiently supported to be called drivable.

Preserve useful returns; transform at acquisition time

Native transport preserves finite XYZ returns. Input filtering removes invalid/range-boundary returns and enforces the declared 0.5–100 m radial range, not a ground-height or robot-footprint crop. Apply the same pose to points and LiDAR origin.

Accumulate bounded, expiring geometric layers

Each 10 cm XY cell keeps up to three normal height layers plus a conservative overflow layer that cannot define ground. A 2.5 cm association band groups heights; it is not 10 cm vertical voxel quantization. Counts, scatter, extrema, view/support and 5×5 within-cell XY-presence metadata summarize returns.

Estimate local ground, then measure relative height

A robust local plane uses the lowest plausible surface layers in a 9×9 neighborhood. Ground tolerance is 3 cm; uncertainty limit 2 cm; maximum slope 0.35 rise/run (about 19.3°). Evaluate residuals relative to that plane: a sloped surface is not automatically a vertical obstacle.

Keep ground evidence separate from boundary evidence

The two-path candidate also classifies native-chunk surface/boundary evidence before pooling. This helps distinguish consistent support from motion/registration scatter. Ground votes cannot erase independent step, wall or dropoff evidence. The resolved-boundary variant avoids a redundant supplemental unknown halo at an already occupied source; conservative boundary guards remain.

Classify hazards and check connectivity

Use relative 8 cm positive hazards, negative edges, surface extent and uncertainty. Steep/mixed or inadequately modelled regions remain unknown or occupied. Connect compatible supported surfaces; bounded interpolation spans at most 30 cm and must satisfy its geometric support checks.

Require whole-cell support and clearance

A return at the cell center is not enough. Corner/angular coverage and bounded span certificates prevent bridging unobserved hole rims. Clearance/occlusion checks reject apparent ground hidden by a face. Missing returns never establish free space.

Project six outputs; publish one advisory cost grid

The C API returns cost, reason, ground height, uncertainty, obstacle height and age. The ROS wrapper publishes the cost channel and archives hashes for all six. Evidence expires after 30 s in immutable ≤1 s buckets; fresh hits do not rejuvenate old extrema.

07 / Controlled motion, not autonomous planning

The loop driver—and the assumption we fixed

Declared loop16 route

Initial planar-base coordinates, metres:
(0,0) → (2,0) → (2,−6) → (0,−6) → (0,0)
Four clockwise 90° turns; final original heading.
Translation 0.10 m/s; rotation ≤0.10 rad/s.
Nominal translation dose: 16 m.

The acquisition driver uses GT and a surveyed clear corridor. The shadow mapper and collector do not publish velocity commands. No simultaneous Nav2, teleop or other command owner is allowed.

Fixed post-turn connection, version 2

Version 1 allowed up to 25 cm displacement during a turn, then required the next translation to already lie within 8 cm of the nominal straight line. A legal turn could therefore fail at the transition.

frozen_post_turn_connection_v2 freezes the actual first GT translation pose as the start, then steers toward the unchanged next waypoint. Cross-track error is measured against that immutable connection, not a continuously re-fitted path.

Guards retained, not loosened to make a test pass

  • Independent preflight: 17,072 physical survey samples at 5 cm spacing over the inflated route region; floor support and relative roughness/slope checks.
  • Physical envelope: acquisition footprint half-extents 0.85 × 0.70 m, turn-center offset ≤25 cm, straight cross-track ≤8 cm, heading error ≤0.15 rad. The connector cannot extend beyond the originally surveyed center envelope.
  • Time and authority: 0.5 s wall heartbeat, 1.5 s stall limit, bounded leg deadlines, 1,800 s experiment wall cap, sole publisher, recorder readiness lease and stop/revoke on failure.
  • Auditability: changed route version/hash, first-pose anchors retained in every command/reached row, immutable-anchor and endpoint audit. Failed v1 recordings stay failed.
Latest rerun: the transition fix worked; a different failure stopped the experiment.First 2 m leg and 90° turn completed; the next connection advanced 1.991 m with maximum 1.98 mm cross-track error. The later stop was a simulation heartbeat expiry, not the previous nominal-line rejection. Actual total GT travel was 4.25 m, not a completed 16 m loop.

Guardrails against accidental “cheating”

Freeze the inputs and denominator

Retain raw recordings, reference hashes, mount/config/library hashes, route version, seed, acquisition dose and grid phase. Compare all frames, including the worst positive/dropoff false-free result—not just the final pretty map. Unknown and outside-grid reference cells remain in the declared coverage denominator.

GT labels stay in evaluators. Do not substitute longer evidence lifetime, more motion, fitted pose alignment or a visibility mask without declaring a different experiment.

Preserve failures and causal limits

Exclusive-create archives; no overwriting failed attempts. Missing scans, missing pose brackets and reset epochs cannot be interpolated away. First-published and final-revised scores are separate. A failed-prefix diagnostic always retains acceptance:false.

Development grid phases are not new held-out scenes. Unit tests, isolated compute tests and a requested repeat do not replace a completed, independently scored live mission.

Full numerical history, counterexamples and retained failures: implementation-plan.md. The numbers here are a dated snapshot, not a live dashboard.

12 / Promotion criteria

What has to happen before large-scale navigation?

  1. Attribute and fix runtime stalls. Separate simulator/GC, native callback, ROS serialization, archive I/O and terrain projection costs. Keep timing failures and unchanged watchdogs; demonstrate live p95/p99 compliance rather than selecting the fastest repeat.
  2. Close the shutdown/invalidation gap. Test SIGINT between integration and projection, failure publication, queue flushing and completion sealing. Require unambiguous invalid/incomplete status and explicit counts for every terminal path.
  3. Finish the declared loop with the frozen estimator/mapper. Validate v2 driver anchors, complete native stream, all first-published associations, route-wide accuracy and sequence terrain safety. A return near the start is not itself a loop-closure optimization test.
  4. Generalize without retuning the denominator. Freeze the candidate and thresholds; run independently declared natural seeds/routes, turns, grid offsets and fault injections. Track positive hazards, dropoffs, coverage, latency and reset behavior separately.
  5. Promote through a separate navigation integration gate. Define map age/validity authority, conservative unknown policy, footprint-area and swept-motion collision vetoes, obstacle-distance cost gradient and command mux behavior. Test stop-on-stale/reset/mapper-exit before allowing autonomous goals.
  6. Then expand global behavior. Rolling/local versus long-term mapping, evidence expiry during long routes, graph correction rebuilds and recovery/exploration policy need explicit designs and their own tests. Do not enable global pose changes over stale accumulated terrain.
Current decisionKeep the terrain mapper advisory and the route driver independently guarded. The next decisive experiment is a completed, timing-qualified controlled loop, not a wider autonomous campaign or another unexplained GLIM parameter sweep.
